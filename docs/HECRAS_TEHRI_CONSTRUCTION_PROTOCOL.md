## 2. Comprehensive Construction Specification (Items A through O)

### **A. Which Files HEC-RAS Requires:**
1. `<Project>.prj`: Master project file defining units, active plan, geometry, and flow references.
2. `<Project>.g##`: ASCII Geometry definition (2D flow area polygon, boundary condition lines, SA/2D connections).
3. `<Project>.g##.hdf`: Compiled binary hydraulic geometry tables (generated by `RasGeomPreprocess.exe`).
4. `<Project>.u##`: ASCII Unsteady Flow data (boundary hydrographs, normal depth friction slopes, initial WSE).
5. `<Project>.p##`: ASCII Plan specification (simulation time window, computation timestep, breach parameters, output intervals).
6. `<Project>.b##` / `<Project>.bco##`: Boundary condition compiled binary control tables.
7. `<Project>.rasmap`: XML mapping configuration defining the terrain association and coordinate system.
8. `<TerrainName>.hdf`: HEC-RAS Terrain definition containing tiled elevation pyramids.

---

### **B. Which Files Can Be Created Programmatically:**
The text-based HEC-RAS configuration files can be generated programmatically using valid ASCII HEC-RAS keyword syntax:
- `.prj` (Project Header & file indices)
- `.g01` (2D Flow Area boundary coordinates, internal connection lines, station-elevation pairs)
- `.u01` (Boundary condition assignments, initial reservoir elevation)
- `.p01` (Plan simulation window, calculation options, breach trigger and geometry)
- `.rasmap` (Terrain layer XML schema)

---

### **C. Which Files Must Be Generated by HEC-RAS Preprocessing:**
- **`RasGeomPreprocess.exe`** must compile `.g01` against the Terrain HDF to generate:
  1. `.g01.hdf` (Cell centers, face points, elevation-volume tables for every 2D cell, area-elevation tables for every face).
  2. `.c01` / `.x01` (Connectivity indices and spatial matrices).
- These binary tables cannot be hand-crafted without running the official USACE geometric preprocessor.

---

### **D. How Terrain is Imported:**
1. The derived GeoTIFF (`tehri_pilot_utm44n_25m.tif`) is placed in a `Terrain/` directory.
2. A `.prj` spatial reference file with the UTM Zone 44N projection WKT is associated with the raster.
3. HEC-RAS generates `Terrain.hdf` with multi-resolution elevation tiling and property tables.

---

### **E. How 2D Flow Areas are Defined:**
- Defined in `.g01` under keyword `2D Flow Area: <AreaName>`:
  - `Perimeter=<N_points>` followed by $(X, Y)$ coordinate pairs in UTM Zone 44N.
  - Base cell dimensions: `Cell Size=<Δx>,<Δy>` ($25\text{ m} \times 25\text{ m}$).
  - Manning's $n$: Default $n = 0.045$.

---

### **F. How Mesh is Generated:**
- The USACE mesh generator builds orthogonal cell centers, cell faces, and face points within the perimeter polygon.
- Invert elevation for each cell is extracted by cell-subsurface polygon integration across the underlying Terrain HDF.

---

### **G. How Breaklines are Created:**
- Defined under `2D Flow Area Break Line: <LineName>`:
  - Polyline coordinates tracing the Bhagirathi canyon thalweg or road embankments.
  - Refinement parameters: `Near Cell Spacing=10.0`, `Far Cell Spacing=25.0`, `Near Repeats=1`.

---

### **H. How Manning Zones are Defined:**
- Set via spatial land cover layer or default uniform parameter in `.g01`:
  `Mann N Def=<AreaName>,0.045`

---

### **I. How SA/2D Connections (Dam Embankment) are Defined:**

  - Line coordinate points spanning from left abutment to right abutment across the valley at $(30.378^\circ\text{N}, 78.480^\circ\text{E})$.

  - Weir Coefficient: $C_w = 2.6\text{ (US Customary)} \approx 1.44\text{ (SI)}$.
